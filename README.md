## 🎯 Обратная механика найма (Reverse Recruiting) — 35% баллов

В отличие от классических площадок, где соискатели откликаются вслепую, а работодатели тонут в сотнях нерелевантных резюме:
1. **Инициатива у работодателя**: Соискатель проходит адаптивное тестирование и подтверждает свой спортивный опыт в ФСП, получая объективную категорию (`Специализация × Грейд`).
2. **Работодатель ищет по верифицированным категориям**: Система ранжирует кандидатов с **прозрачной объяснимостью (Explainable AI)**.
3. **Обязательная вилка зарплаты до контакта**: Приглашение соискателю строго содержит вилку зарплаты в рублях («от–до»).
4. **Защита контактов по 152-ФЗ**: Контакты кандидата (ФИО, телефон, email, TG) **физически отсутствуют** в ответах API до момента, пока кандидат явно не примет приглашение (`ACCEPTED`).

```
[Работодатель] --(Описывает потребность с вилкой ₽)--> [Ранжированная витрина категорий]
                                                                 │
[Обезличенная карточка (псевдоним, θ, ФСП)] <─────────────────────┘
         │
         ▼ (Направляет приглашение с обязательной вилкой зарплаты)
[Соискатель видит компанию, условия и вилку ₽]
         │
         ├── [Принять] ────► Статус ACCEPTED ──► Контакты РАСКРЫТЫ работодателю (запись в audit_log)
         └── [Отклонить] ──► Статус DECLINED ──► Контакты остаются СКРЫТЫМИ
```

## 💡 Ключевые преимущества

- **Защита от утечек заданий (Anti-Leak Engine)**: Шаблоны параметризованы случайными переменными $N, K$, структурами и кодом. Эталонный ответ и дистракторы считаются детерминированным чекером. Слив ответов бесполезен!
- **Математически строгая психометрика (2PL IRT + Bayes EAP)**: Способность $\theta$ оценивается байесовским интегралом Гаусса-Эрмита. Метод EAP никогда не расходится в бесконечность.
- **Explainable AI**: Для каждой рекомендации формируется понятное обоснование («Backend Middle, топ-12% категории, стек 4 из 4, серебро на Чемпионате ФСП, ожидания в вилке»).
- **Справедливость для кандидатов без ФСП**: Веса компонентов ранжирования автоматически перенормируются к 1.0. Кандидат без спортивной истории не штрафуется!
- **Энергоэффективный и быстрый запуск**: Замена тяжелого 2.2 ГБ PyTorch/bge-m3 на легковесный ONNX Runtime CPU + PostgreSQL Russian FTS (потребление RAM < 1.5 ГБ).

## 🧠 Адаптивное тестирование и защита от утечек

Каждое задание генерируется на лету:
* Вероятность правильного ответа по модели Бирнбаума:
  $$P_i(\theta) = \frac{1}{1 + e^{-1.7 a_i (\theta - b_i)}}$$
* Информация Фишера:
  $$I_i(\theta) = (1.7 a_i)^2 P_i(\theta) (1 - P_i(\theta))$$
* Выбор вопроса с максимумом информации $I_i(\hat{\theta})$ с randomesque выборкой из топ-3 (защита от переэкспонирования).
* Критерий остановки: $SE(\hat{\theta}) \le 0.35$ или лимит 8–15 вопросов.

## 🔒 Безопасность и 152-ФЗ

* **Физическая изоляция на уровне сериализации**: Поля `first_name`, `last_name`, `phone`, `email`, `telegram` отсутствуют в Pydantic схеме `CandidatePublicCard`.
* **Юридический аудит**: Любой переход в статус `ACCEPTED` фиксируется в таблице `audit_log` с IP-адресом и временной меткой.
* **Версионированные согласия**: Согласие на обработку ПДн и публикацию обезличенного профиля сохраняется с версией и датой.

## 🚀 Быстрый запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/Shtirlitc69/Hacaton_FSP_Phaeton.git
cd Hacaton_FSP_Phaeton
```

### 2. Запуск через Docker Compose (Рекомендуется)
```bash
cp .env.example .env
docker compose up --build -d
make seed
```
* **Веб-интерфейс**: `http://localhost:3000`
* **Swagger API (OpenAPI)**: `http://localhost:8000/docs`
* **Mailpit (Почтовый ящик)**: `http://localhost:8025`

### 3. Локальный запуск без Docker
```bash
# Запуск тестов бэкенда
python -m pytest backend/tests -v

# Запуск научной валидации
python -m validation.run_all

# Генерация официального PDF-отчета
python scripts/generate_project_pdf.py
```
